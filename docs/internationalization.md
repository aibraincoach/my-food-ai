# Language files and checks

Slice 1 of #1218 supplies the mechanism and the Profile Language setting. It does **not** translate the rest of the app yet. The supported languages are English and Japanese; the Japanese has an AGY translation and an independent model back-translation check, **not native-speaker approval**.

Messages live in `messages/en.json` and `messages/ja.json`. `src/i18n/request.ts` resolves the device's explicit `lang` cookie, otherwise English. Phone-language negotiation is implemented but switches on only with the translated front screens in slice 2. English is never a per-key fallback. Until slice 2, the root request-time Suspense document keeps `html lang="en"`, since the app outside the Language row is English. The translated row declares its own `lang`. Explicit device choices still persist; there is no URL prefix or internal rewrite. Previously static documents become dynamic. Client providers receive only the namespaces their screen uses.

`npm run check:messages` checks both key sets, empty values, ICU syntax and argument signatures, then lints converted code. Locale-specific plural categories can differ, but argument names/types, select choices, exact-number cases, offsets and tags must match. Both the normal prebuild hook and the disposable app build run this check; the test runner runs it too. Runtime `onError` and `getMessageFallback` throw.

`scripts/eslint-i18n.mjs` declares the temporary migration exemptions. Each later slice shrinks them, expands `lintTargets` to the converted area, and converts that area's fixed JSX text, user-facing attributes and error/message strings. The last slice deletes the exemptions and lints all of `src`. Slice 1 checks `src/i18n` and `src/components/i18n`; existing screens outside those directories remain for the later packets.

The setting writes one device cookie, with no profile write or migration. The non-secret preference cookie is Secure for a configured HTTPS `APP_URL`; absent configuration, production defaults to Secure. A failed write is visible and is attempted once. The setting waits for the worker's language acknowledgement before refreshing server content. A document also reports its locale on mount and controller changes, so an older controller can update normally without blocking the page.

The worker pre-caches `/shell?lang=en` and `/shell?lang=ja` with credentials omitted. A shell-only middleware branch supplies that explicit locale and returns before Auth is constructed. The worker stores only the last language code in its existing control cache and keeps a per-client map. A restart recovers that code. An unknown locale or absent matching shell uses the network; it never serves the other locale's shell. A failed network stays failed. The anonymous Welcome `/` cache's per-locale conversion is required in slice 2, when Welcome itself is translated.

The server and client provider receive the same validated `time-zone` cookie, using the existing `validZone` helper. With no known zone it uses that helper's UTC default. New number/date formatting helpers take the active locale; date calls require an explicit viewing zone. Do not format dates using the host's implicit zone.

Focused checks: `node --import tsx --test tests/i18n.test.mjs tests/i18n-action.test.mjs tests/sw-media-cache.test.mjs tests/verified-user.test.mjs`. The loopback-only browser acceptance is `tests/browser/i18n.mjs`; it requires a disposable app, a ledgered session file and an output directory, never production credentials. Keep fixture/session artifacts outside the repository.
