# Language files and checks

Slices 1 and 2 of #1218 supply the mechanism, the Profile Language setting, the front auth screens, About, errors, navigation and the live card. Capture and the other Home/Days/Profile screens remain for later slices. The supported languages are English and Japanese; slice 2 adds 131 keys: 22 translated by AGY and 109 drafted by the PM, all with an independent model back-translation check. Together with the six Language keys there are 137 keys per language, **not native-speaker approval**.

Messages live in `messages/en.json` and `messages/ja.json`. `src/i18n/request.ts` resolves the device's explicit `lang` cookie, then a supported weighted phone language from `Accept-Language`, then English. English is never a per-key fallback. The root request-time Suspense document emits the resolved `html lang` together with the translated front screens; there is no URL prefix or internal rewrite. Previously static documents become dynamic. Client providers receive only the namespaces their screen uses.

`npm run check:messages` checks both key sets, empty values, ICU syntax and argument signatures, then lints converted code. Locale-specific plural categories can differ, but argument names/types, select choices, exact-number cases, offsets and tags must match. Both the normal prebuild hook and the disposable app build run this check; the test runner runs it too. Runtime `onError` and `getMessageFallback` throw.

`scripts/eslint-i18n.mjs` declares the temporary migration exemptions. Each later slice shrinks them, expands `lintTargets` to the converted area, and converts that area's fixed JSX text, user-facing attributes and error/message strings. The last slice deletes the exemptions and lints all of `src`. Slice 2 expands the converted scope to auth, About, errors, navigation and the card presentation reader. Remaining capture/Home screens are later packets. `HELD_FOR_OWNER_WORDING` visibly lists the owner-gated exceptions; it is not a translation fallback.

The setting writes one device cookie, with no profile write or migration. The non-secret preference cookie is Secure for a configured HTTPS `APP_URL`; absent configuration, production defaults to Secure. A failed write is visible and is attempted once. The setting waits for the worker's language acknowledgement before refreshing server content. A document also reports its locale on mount and controller changes, so an older controller can update normally without blocking the page.

The worker pre-caches `/shell?lang=en` and `/shell?lang=ja` with credentials omitted. An anonymous shell/Welcome middleware branch supplies that explicit locale and returns before Auth is constructed. The worker stores only the last language code in its existing control cache and keeps a per-client map. A restart recovers that code. An unknown locale or absent matching shell uses the network; it never serves the other locale's shell. A failed network stays failed. The anonymous `/` and `/welcome` copies are also keyed per language and never borrow another language's copy. The shell's locale and navigation are translated; unconverted Home content waits for slice 4.

The server and client provider receive the same validated `time-zone` cookie, using the existing `validZone` helper. With no known zone it uses that helper's UTC default. New number/date formatting helpers take the active locale; date calls require an explicit viewing zone. Do not format dates using the host's implicit zone.

Focused checks: `node --import tsx --test tests/i18n.test.mjs tests/i18n-action.test.mjs tests/sw-media-cache.test.mjs tests/verified-user.test.mjs`. The loopback-only browser acceptance is `tests/browser/i18n.mjs`; it requires a disposable app, a ledgered session file and an output directory, never production credentials. Keep fixture/session artifacts outside the repository.

Live cards carry numeric/structured presentation inputs and use one formatter for their reader language. Stored PNGs explicitly use English until #1220. Stored unavailable-reason sentences and matcher detail stay unchanged under #1253; no English text parsing is used.

The approved #1243/#1253 copy adds six keys and updates three, bringing each language to143 keys. It replaces the Welcome hero, metadata description, table caption/source note and three About paragraphs. Metadata resolves the active language through generateMetadata. The nutrition table uses the existing foodApproximation reader: only estimate-kind foods get a named model-estimate note; closest references and unknown historical sources do not. Open Food Facts attribution remains unchanged. The caption is screen-reader only. Stored unavailable-reason leads remain in HELD_FOR_OWNER_WORDING; stored PNGs remain English.
