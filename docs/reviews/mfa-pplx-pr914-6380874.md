PR #914 (fix: Fleet 21 lease-heartbeat) is a clean, minimal fix that reduces the worker lease TTL from 300 seconds to 60 seconds and adds a 20-second heartbeat in runWorker so a killed worker's lease frees the queue within ~60 seconds. The implementation is sound and ready to merge once you account for a couple of minor observability and defensive-coding details.

What Works Well

Centralized constants: LEASE_TTL_SECONDS = 60 and LEASE_HEARTBEAT_MS = 20_000 are defined once in src/lib/queue/lease.ts and imported by both src/lib/worker/drain.ts and src/app/api/jobs/tick/route.ts.

Safe timer cleanup: clearInterval(heartbeat) is placed inside the finally block in runWorker (src/lib/worker/drain.ts), ensuring the interval is cleared whether the worker finishes normally or throws.

No unhandled rejections: The interval callback attaches .catch(() => {}) to renewLease(...), preventing a transient renewal error from crashing the worker process.

Verification: docs/evidence/fleet21/lease-condition-check.md records a 59.977-second takeover measurement after SIGKILL on the disposable stack, along with passing results for all 13 targeted worker tests, the production build, and tsc --noEmit.

Potential Issues and Edge Cases

Silent heartbeat failures: void renewLease(admin, holder, LEASE_TTL_SECONDS).catch(() => {}) swallows all errors without logging. If renewals fail for 60 seconds, a second worker can start concurrently; logging a warning on failure would make that visible in production.

Event loop retention: Calling heartbeat.unref?.() after setInterval is a low-cost safeguard in Node.js so the timer cannot accidentally keep the process alive if anything unexpected occurs outside try/finally.

Default parameters elsewhere: Passing LEASE_TTL_SECONDS explicitly to queueTick and renewLease works here, but any other caller of tryAcquireLease, renewLease, or queueTick that omits the TTL argument will still fall back to the existing 300-second default.

Overlapping renewals: If a renewLease RPC ever stalls for more than 20 seconds under database load, setInterval will fire a second concurrent renewal. This is generally benign if the RPC is idempotent, though worth keeping in mind.

Recommendation

Approve and merge once your required external review and PM merge order are complete; optionally add a console.warn (or structured logger call) inside the heartbeat .catch() and heartbeat.unref?.() for better observability.
